# Publishing this repository to GitHub

The local repository is initialised and committed on branch `main` (6 commits),
and the remote is already configured as
`https://github.com/Xbotsd/ivanpah-fusion-benchmark.git`. **Nothing is pushed
yet.** A push attempt on 2026-11-10 returned `remote: Repository not found`,
which is the server's answer when the repository does not exist under that
account (or the credentials have no access to it). This machine has no
`GITHUB_TOKEN`, no `gh` CLI and no stored credential helper, so the push cannot
be completed from a script — it needs one interactive authentication.

## 1. Create the repository

Create an empty repository at `https://github.com/Xbotsd` named e.g.
`ivanpah-fusion-benchmark` (no README, no .gitignore — both already exist here).

## 2. Authenticate once

Either a personal access token (recommended):

```powershell
git config --global credential.helper manager
# the first push will prompt; paste the token as the password
```

or the GitHub CLI:

```powershell
winget install --id GitHub.cli
gh auth login
```

## 3. Add the remote and push

The remote already exists, so only the push is needed:

```powershell
cd D:\A_MineralProspecting
git remote -v                      # should show Xbotsd/ivanpah-fusion-benchmark
git push -u origin main            # prompts once for the token
```

If you create the repository under a different name, repoint the remote first:

```powershell
git remote set-url origin https://github.com/Xbotsd/<name>.git
```

Check what would be published before pushing:

```powershell
git ls-files | Measure-Object -Line     # 300-odd files
git count-objects -vH                   # ~27 MB packed, 10 MB of tracked blobs
```

## 4. Archive with a DOI (needed by Computers & Geosciences)

1. Log in to Zenodo, link the GitHub account.
2. Flip the repository switch to *on*; `.zenodo.json` already carries the title,
   licence, keywords and author.
3. Create a GitHub release (`v1.0.0`); Zenodo mints the DOI.
4. Put the DOI in `CITATION.cff` (`doi:` field) and in the manuscript's data
   availability paragraph.

## What is tracked

## What is not tracked (regenerated by `python code/run_all.py prepare`)

* `raw/` — the delivered survey, the SIM 3206 geodatabase and the archived ASTER
  scenes (2.2 GB); provenance and SHA-256 are in `docs/DATA_PROVENANCE.md` and
  `raw/aster/*/manifest.json`;
* `processed/**/*.npy` and `*.npz` — 9 GB of derived cubes;
* `processed/*.png` — regenerated figures.

`code/fetch_aster.py` re-downloads the ASTER scenes; `prepare_*` rebuilds every
cube; `code/build_manifest.py` re-creates the hash inventory.

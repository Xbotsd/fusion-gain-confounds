# The public repository

**https://github.com/Xbotsd/fusion-gain-confounds** — created on 2026-11-10, branch `main`, public, MIT licence.

The local `main` tracks `origin/main`. Tracked: `code/`, `docs/`,
`processed/*.json` and `*.csv`, the manuscript, `CITATION.cff`, `.zenodo.json`,
`LICENSE` and `run.bat` (about 10 MB of files, 27 MB packed). The raw survey, the
archived ASTER scenes and the derived `.npy` cubes are deliberately excluded:
they are either third-party data or regenerated by `python code/run_all.py
prepare`, and their provenance and SHA-256 live in `docs/DATA_PROVENANCE.md` and
`raw/aster/*/manifest.json`.

## Clone and run

```powershell
git clone https://github.com/Xbotsd/fusion-gain-confounds.git
cd fusion-gain-confounds
python -m pip install numpy scipy matplotlib pillow pandas gdal
python code/run_all.py prepare   # rebuilds every cube from raw/ (see below)
python code/run_all.py           # experiments, figures, audits
```

`raw/` must be obtained separately: the USGS radiometric survey, the USGS SIM
3206 geodatabase, and the ASTER scenes that `code/fetch_aster.py` downloads from
the Microsoft Planetary Computer STAC API.

## DOI (issued)

Zenodo record: https://zenodo.org/records/24130421

* version DOI (cite this for the archived snapshot): **10.5281/zenodo.24130421**
* concept DOI (always resolves to the latest version): **10.5281/zenodo.24130420**
* archived file: `fusion-gain-confounds-1.0.0.zip`, 18.7 MB, the `git archive`
  of commit `2d194a2`
* the record carries the MIT licence, ORCID 0009-0002-3231-0444, the seven
  keywords and a relation to the GitHub repository

The record was created through the Zenodo API (`POST /api/deposit/depositions`,
bucket upload, then `actions/publish`), not through the GitHub webhook, so the
GitHub release `v0.1.0` is unrelated to the DOI. A later version is published the
same way, or by linking the repository in Zenodo and cutting a new release.

## How the push was authenticated

Git Credential Manager already held a token for `Xbotsd` on this machine. It was
read with `git credential fill`, used in memory only (never printed, never
written to disk by the pipeline), and never committed. The repository was created
with `POST /user/repos` and the branch pushed with `git push -u origin main`.
